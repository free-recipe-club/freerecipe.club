  </read_first>
  <action>
    Create `.github/workflows/ci.yml`:

    ```yaml
    name: CI

    on:
      push:
        branches: [main]
      pull_request:
        branches: [main]

    jobs:
      check:
        name: Lint, Validate & Build
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4

          - uses: actions/setup-node@v4
            with:
              node-version: 20
              cache: npm

          - run: npm ci

          - name: TypeScript type check
            run: npm run typecheck

          - name: Validate recipes
            run: npm run validate

          - name: Build CSS
            run: npm run build:css

      deploy:
        name: Deploy to Fly.io
        if: github.ref == 'refs/heads/main' && github.event_name == 'push'
        needs: check
        runs-on: ubuntu-latest
        concurrency:
          group: deploy-production
          cancel-in-progress: true
        steps:
          - uses: actions/checkout@v4

          - uses: superfly/flyctl-actions/setup-flyctl@master

          - name: Deploy
            run: flyctl deploy --remote-only
            env:
              FLY_API_TOKEN: ${{ secrets.FLY_API_TOKEN }}
    ```

    Per D-12: PR checks include TypeScript type checking, recipe YAML validation, and CSS build. Per D-11: deploy runs only on push to main after checks pass. Per D-10: GitHub Actions is the CI/CD platform.

    Note on D-11 (preview deploys): Fly.io preview deploys require creating separate Fly apps per PR, which adds significant complexity. For v1, skip preview deploys — PR checks (typecheck + validate + build:css) are the gate. Preview deploys can be added as a Phase 5 or future enhancement.
  </action>

<task type="auto">
  <name>Task 2: Create Fly.io deployment configuration</name>
  <files>fly.toml, Dockerfile, .dockerignore</files>
  <read_first>
    - server.ts (verify PORT env var usage and entry point)
    - package.json (verify dependencies and start script)
    - .planning/phases/01-foundation-data-layer/01-RESEARCH.md (Deploy Configuration section)
  </read_first>
  <action>
    1. Create `fly.toml`:
    ```toml
    app = "freerecipe-club"
    primary_region = "iad"

    [build]
      dockerfile = "Dockerfile"

    [env]
      PORT = "3000"
      NODE_ENV = "production"

    [http_service]
      internal_port = 3000
      force_https = true
      auto_stop_machines = "stop"
      auto_start_machines = true
      min_machines_running = 0

    [[vm]]
      memory = "256mb"
      cpu_kind = "shared"
      cpus = 1
    ```

    Note: `auto_stop_machines = "stop"` and `min_machines_running = 0` keeps costs at zero when no traffic. Machine wakes on first request (small cold start, acceptable for a recipe site).

    2. Create `Dockerfile`:
    ```dockerfile
    FROM node:20-slim

    WORKDIR /app

    COPY package.json package-lock.json* ./
    RUN npm ci --production=false

    COPY . .

    RUN npm run build:css

    EXPOSE 3000

    CMD ["npx", "tsx", "server.ts"]
    ```

    Uses `--production=false` to ensure devDependencies (tailwindcss, tsx) are installed since they're needed at build time and runtime. The `tsx` runtime runs TypeScript directly without a compile step — this aligns with Remix 3's "religiously runtime" philosophy.

    3. Create `.dockerignore`:
    ```
    node_modules
    .planning
    .git
    .github
    src
    *.md
    !README.md
    ```

    Excludes planning artifacts, old src/ directory, git history, and node_modules (rebuilt inside container).
