## Spacing Scale

Inherited from Phase 2 baseline. Cooking-mode-specific usages noted:

| Token | Value | Usage in Cooking Mode |
|-------|-------|----------------------|
| xs | 4px | Progress bar height |
| sm | 8px | Gap between ingredient list items, exit button internal padding |
| md | 16px | Page horizontal padding, ingredient panel internal padding, gap between prev/next buttons |
| lg | 24px | Gap between ingredient panel and step text, step card vertical padding |
| xl | 32px | Bottom navigation area top padding (separation from step content) |
| 2xl | 48px | Not used in cooking mode |
| 3xl | 64px | Not used in cooking mode |

Exceptions:
- Navigation button height: 56px — exceeds the 48px minimum from D-06 for wet-hand usability. Button width: each button occupies half the viewport width minus 24px total gap (16px between buttons + 16px page margins each side).
- Exit button tap target: 44px × 44px minimum effective area (achieved via padding around the "✕" character).
- On step 1, Previous is hidden and Next takes full width.

## Typography

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Step text | 24px | 400 | 1.5 | `text-2xl leading-normal` |
| Ingredient item | 20px | 400 | 1.4 | `text-xl` |
| Ingredient group heading | 20px | 700 | 1.3 | `text-xl font-bold` |
| Step counter | 16px | 700 | 1.5 | `text-base font-bold` |
| Button label | 20px | 700 | 1.0 | `text-xl font-bold` |
| Exit label | 14px | 400 | 1.0 | `text-sm` |

**Weights used:** 400 (regular) and 700 (bold) — consistent with Phase 2.

**Scale rationale:** 24px step text (D-12) is sized for reading at arm's length — a phone propped on a counter ~60 cm away. Ingredient items at 20px are secondary but still comfortably legible. Button labels share the 20px tier with ingredients — bold weight differentiates them.

### Accent Reserved For (exhaustive list)
- Progress bar fill

- Never for body text, borders, or decorative elements within cooking mode

### Implementation Approach

CSS custom properties on `.cook-mode` class, overridden by `@media (prefers-color-scheme: dark)`:

```css
.cook-mode {
  --cook-bg: #fdf6e3;
  --cook-surface: #f0ead4;
  --cook-text: #111827;
  --cook-text-secondary: #4b5563;
  --cook-accent: #2d5016;
  --cook-btn-bg: #2d5016;
  --cook-btn-text: #ffffff;
}

@media (prefers-color-scheme: dark) {
  .cook-mode {
    --cook-bg: #1c1917;
    --cook-surface: #292524;
    --cook-text: #fafaf9;
    --cook-text-secondary: #a8a29e;
    --cook-accent: #86c166;
    --cook-btn-bg: #86c166;
    --cook-btn-text: #1c1917;
  }
}
```

This scopes dark mode to cooking mode only. The recipe detail page, listing page, and home page remain cream-only regardless of system preference.

## Layout Contract

### Cooking Mode Page (`/recipes/:slug/cook`)

Full-viewport immersive experience. No navigation bar, no header, no footer (D-11). The `.cook-mode` class on the outermost element scopes all cooking mode styles.

**Viewport structure (top to bottom):**

```
┌──────────────────────────────────┐
│ [✕]          Step 3 of 8         │  Top bar
│ ████████████░░░░░░░░░░░░░░░░░░░░ │  Progress bar (4px)
├──────────────────────────────────┤
│                                  │
│  ┌────────────────────────────┐  │
│  │  Doughnuts                 │  │  Ingredient panel
│  │  · 2 c all-purpose flour   │  │  (only if step has matches)
│  │  · 2 tsp baking powder     │  │
│  │  · 1 tsp kosher salt       │  │
│  └────────────────────────────┘  │
│                                  │
│  Whisk flour, pumpkin pie        │  Step text (24px)
│  spice, baking powder, and       │  (vertically centered in
│  salt in a bowl.                 │   remaining viewport space)
│                                  │
├──────────────────────────────────┤
│  [← Previous]     [Next →]      │  Navigation (56px buttons)
└──────────────────────────────────┘
```

**Top bar:**

| Element | Position | Style |
|---------|----------|-------|
| Exit button | Top-left | "✕", 14px regular, `--cook-text-secondary`, 44px tap target via padding |
| Step counter | Centered | "Step {n} of {total}", 16px bold, `--cook-text-secondary` |
| Progress bar | Full width, below counter | 4px height, track `--cook-surface`, fill `--cook-accent`, fill width = `(n / total) × 100%` |

**Ingredient panel:**

| Property | Value |
|----------|-------|
| Visibility | Rendered only when current step has matched ingredients |
| Background | `--cook-surface` |
| Border radius | 8px |
| Padding | 16px |
| Margin | 0 16px (aligns with page horizontal padding) |
| Group heading | 20px bold, `--cook-text` |
| Item text | 20px regular, `--cook-text` |
| Item spacing | 8px between items |
| Multiple groups | Each group shows its heading; groups separated by 16px gap |

**Step text area:**

**Primary focal point:** Step text, vertically centered at 24px — the dominant reading element on every step card. All other elements (progress bar, ingredient panel, navigation) are secondary to this.

| Property | Value |
|----------|-------|
| Alignment | Vertically centered in space between progress bar and nav buttons |
| Horizontal padding | 16px |
| Max width | 640px, centered horizontally |
| Text | 24px regular, `--cook-text`, `line-height: 1.5` |
| Overflow | If step text exceeds viewport height, vertical scroll within the step area |

**Navigation buttons:**

| Property | Value |
|----------|-------|
| Layout | Fixed to viewport bottom. Two equal-width buttons in a row, 16px gap between them |
| Margins | 16px horizontal, 16px bottom (safe area for notched phones) |
| Height | 56px |
| Background | `--cook-btn-bg` |
| Text | `--cook-btn-text`, 20px bold |
| Border radius | 8px |
| Step 1 | Previous hidden; Next takes full width |
| Last step | Next label changes to "Finish Cooking" |
| Focus state | 2px outline in `--cook-accent`, 2px offset |

**No-JS fallback (D-04):**
- Server renders ALL steps visible in a vertical scroll layout
- Each step uses the same 24px text + ingredient panel treatment
- Steps separated by a 1px border in `--cook-surface`
- Navigation buttons hidden (no JS to drive them)
- Wake lock unavailable — silent, no error shown
- "Start Cooking" button still visible on recipe detail page (link works without JS)

## Interaction Contract

### Step Navigation

| Property | Value |
|----------|-------|
| Mechanism | Client-side JavaScript — show/hide step elements |
| Initial state | Step 1 visible, all others hidden via JS on load |
| Previous button | Reveals previous step, hides current. Hidden on step 1. |
| Next button | Reveals next step, hides current. Label changes to "Finish Cooking" on last step. |
| Finish Cooking action | Navigates to `/recipes/:slug` (returns to recipe page) |
| Keyboard | Left arrow = previous, Right arrow = next, Escape = exit |
| Animation | None — instant show/hide (no transition library, keeps bundle minimal) |
| State | Current step index stored in JS variable. No URL hash or localStorage. |

### Wake Lock

| Property | Value |
|----------|-------|
| API | `navigator.wakeLock.request('screen')` |
| Activation | Acquired on cooking mode page load (after DOMContentLoaded) |
| Release | Released on page navigation or `visibilitychange` to hidden |
| Re-acquisition | Re-acquire on `visibilitychange` to visible (handles tab switching) |
| Error handling | Silent — if Wake Lock API unavailable or permission denied, no user-facing error |
| Browser support | Chrome 84+, Edge 84+, Safari 16.4+. Older browsers get cooking mode without wake lock. |

### Progress Bar

| Property | Value |
|----------|-------|
| Type | Horizontal linear bar |
| Track | Full viewport width, 4px tall, `--cook-surface` |
| Fill | Left-aligned, width = `(currentStep / totalSteps) × 100%`, `--cook-accent` |
| Transition | `width 200ms ease` on step change |
| Semantics | `role="progressbar"`, `aria-valuenow="{n}"`, `aria-valuemin="1"`, `aria-valuemax="{total}"` |

### Exit Button

| Property | Value |
|----------|-------|
| Label | "✕" (multiplication sign U+2715) |
| Action | Navigate to `/recipes/:slug` |
| Position | Top-left, within top bar row |
| Tap target | 44px × 44px via padding |
| Accessibility | `aria-label="Exit cooking mode"` |

### Ingredient Auto-Matching (D-08, D-09)

| Property | Value |
|----------|-------|
| Timing | Server-side at render time — no client JS needed |
| Source | `components` array from recipe data. Each group: first element is group name, remaining are ingredient strings. |
| Extraction | Parse ingredient name from each string by stripping leading quantity/unit pattern (e.g., "2 c all-purpose flour" → "flour", "3 lg eggs" → "eggs"). Match the extracted name. |
| Matching | Case-insensitive substring match of extracted ingredient names against step text |
| Plurals | Simple handling: "egg" matches "eggs" and vice versa (strip trailing "s" for comparison) |
| Display | Full ingredient string shown in panel (with quantity), not just the matched name |
| Grouping | Matched ingredients grouped by their component group name |
| No match | Ingredient panel hidden entirely for that step |

## Responsive Contract

Mobile-first. Cooking mode is designed for a phone propped on a kitchen counter.

| Breakpoint | Width | Adjustments |
|------------|-------|-------------|
| Base (mobile) | 320px+ | Full viewport, 16px horizontal padding, 24px step text, 56px buttons full width |
| `sm:` | 640px+ | Step text area constrained to max-width 640px, centered. Buttons max-width 640px. |
| `md:` | 768px+ | Increased padding (24px horizontal). Ingredient panel and step text may sit side by side. |
| `lg:` | 1024px+ | Two-column: ingredient panel as left sidebar (240px), step text in main area. Buttons centered at 640px max. |

**Key constraints:**
- All tap targets ≥ 48px (navigation buttons 56px, exit 44px)
- No horizontal scroll at 320px viewport width
- Step text readable at arm's length without zooming (24px body)
- One step fills viewport — no scrolling between steps
- Very long step text: vertical scroll within the step area (not page scroll)
- Safe area padding at bottom for notched phones (`env(safe-area-inset-bottom)`)

## Accessibility Contract

| Requirement | Implementation |
|-------------|---------------|
| Step announcements | `aria-live="polite"` on region wrapping step counter + step text. Step changes are announced to screen readers. |
| Exit button | `aria-label="Exit cooking mode"` |
| Progress bar | `role="progressbar"` with `aria-valuenow`, `aria-valuemin="1"`, `aria-valuemax="{total}"`, `aria-label="Cooking progress"` |
| Keyboard: prev/next | Left arrow = previous step, Right arrow = next step |
| Keyboard: exit | Escape = exit cooking mode (navigate to recipe page) |
| Focus management | On step change, focus moves to the step text area |
| Color contrast | All text/background combos meet WCAG AA — see Contrast Verification table |
| Reduced motion | Progress bar transition respects `prefers-reduced-motion: reduce` — set `transition: none` |
