<objective>
Add YAML ingredient format validation rules and simplify the extraction regex to support reliable inline quantity annotation in cooking mode.

Purpose: The current ingredient extraction regex cannot parse compound quantities like "1 15 oz can pumpkin puree" — the unit tokens pile up and the name extraction fails, causing wrong quantities to display in cooking mode. Rather than making the regex infinitely clever, constrain the input: add Zod validation rules that enforce a parseable ingredient format (simple `<number> <unit> <name>` or parenthetical sub-quantities like `1 can (15 oz) pumpkin puree`), fix the existing recipe YAML to comply, and simplify the extraction code.

Output: Validated ingredient format, corrected recipe YAML, simplified extraction in cook.tsx.
</objective>

```typescript
function extractIngredientName(ingredient: string): string {
  let stripped = ingredient.replace(
    /^[\d\s./]+(?:c|tsp|tbsp|oz|lb|lg|sm|med|cups?|cans?|pkg|pt|qt|gal|ml|g|kg|inch|cloves?|bunch|head|sticks?|pinch|dash|slices?)\b\s*/i,

  )

  return ingredient.replace(/^[\d\s./]+/, '').trim()
}
```

  <action>
**In `app/data/recipe-schema.ts`:**

Add a Zod `superRefine` on the `components` field that validates each ingredient string (skipping the first element of each group, which is the group name). The validation rule:

1. **Compound unit detection**: Reject ingredients where multiple recognized unit words appear outside of parentheses. Specifically, if after stripping the leading number(s), two or more unit tokens (`c`, `tsp`, `tbsp`, `oz`, `lb`, `cups?`, `cans?`, `pkg`, `pt`, `qt`, `gal`, `ml`, `g`, `kg`) appear before the ingredient name starts, flag it. The regex to detect this pattern:
   ```
   /^\d[\d\s./]*(?:c|tsp|tbsp|oz|lb|cups?|cans?|pkg|pt|qt|gal|ml|g|kg)\b\s+\d[\d\s./]*(?:c|tsp|tbsp|oz|lb|cups?|cans?|pkg|pt|qt|gal|ml|g|kg)\b/i
   ```
   This catches `1 15 oz can` (number-unit-number-unit) but allows `1 can (15 oz)` because the second unit is inside parens.

2. **Error message**: Make it actionable: `Ingredient "{ingredient}" has compound quantity — use parenthetical format instead, e.g., "1 can (15 oz) pumpkin puree"`

3. **Ingredient name minimum**: After stripping quantity and any parenthetical, the remaining name must be at least 2 characters. This catches malformed entries that are all quantity.

Export the compound-unit detection regex as `COMPOUND_QTY_RE` so it can be tested.

**In `data/recipes/pumpkin_doughnut.yml`:**

Change `1 15 oz can pumpkin puree` to `1 can (15 oz) pumpkin puree`.

**In `scripts/validate-recipes.ts`:**

No structural changes needed — it already calls `loadRecipes()` which runs through the Zod schema. Just verify it still works after the schema change.

Update `extractIngredientName` in `cook.tsx` to handle the now-validated parenthetical format. The new logic:

1. Strip leading numbers/fractions: `^[\d\s./]+`


Update `extractQuantity` accordingly — the quantity is everything before the extracted name in the original string (same logic as now, just works correctly with the improved regex).
