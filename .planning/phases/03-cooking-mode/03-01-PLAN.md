**A. Create `app/controllers/recipes/cook.tsx`:**

Create the cooking mode controller with these components:

**1. `escapeHtml()` function** — same pattern as show.tsx:
```typescript
function escapeHtml(str: string): string {
  return str.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;').replace(/"/g, '&quot;')
}
```

**2. `extractIngredientName(ingredient: string): string` function** — strips leading quantity and unit from ingredient strings:
- Regex pattern to strip: `^[\d\s./]+(?:c|tsp|tbsp|oz|lb|lg|sm|med|cups?|cans?|pkg|pt|qt|gal|ml|g|kg|inch|cloves?|bunch|head|sticks?|pinch|dash|slices?)\b\s*`
- Example: `"2 c all-purpose flour"` → `"all-purpose flour"`
- Example: `"3 lg eggs"` → `"eggs"`
- Example: `"1 15 oz can pumpkin puree"` → `"pumpkin puree"`
- Example: `"1 tsp vanilla extract"` → `"vanilla extract"`
- Fallback: if no unit matched, return everything after leading numbers/fractions: `str.replace(/^[\d\s./]+/, '').trim()`

**3. `matchIngredientsToStep(step: string, components: string[][]): { group: string, ingredient: string }[]` function** — server-side ingredient matching:
- For each component group: first element is group name, rest are ingredient strings
- For each ingredient, extract the ingredient name using `extractIngredientName()`
- Two-pass matching against step text (case-insensitive):
  - Pass 1: exact substring match of the full extracted ingredient name in step text
  - Pass 2: for unmatched ingredients, find significant words (≥4 chars, excluding common adjectives like "fresh", "large", "ground", "unsalted", "melted") and check whole-word match in step text
- Simple plural handling: also try stripping trailing "s" or adding "s" for comparison
- Return array of `{ group: groupName, ingredient: fullIngredientString }` for display

**4. `renderCookingMode(recipe: Recipe, slug: string): Response` function** — produce the full HTML page:

The HTML shell is NOT the regular `render()` helper. It's a standalone HTML document with:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{recipe.title} — Cooking — freerecipe.club</title>
  <link rel="stylesheet" href="/styles/output.css">
</head>
<body class="cook-mode" style="background:var(--cook-bg);color:var(--cook-text);margin:0;min-height:100vh;min-height:100dvh">
  <!-- Top bar -->
  <div class="cook-top-bar" style="...">
    <a href="/recipes/{slug}" aria-label="Exit cooking mode" class="cook-exit">✕</a>
    <span class="cook-step-counter" id="cook-step-counter">Step 1 of {total}</span>
  </div>
  <!-- Progress bar -->
  <div role="progressbar" aria-valuenow="1" aria-valuemin="1" aria-valuemax="{total}" aria-label="Cooking progress" class="cook-progress">
    <div class="cook-progress-fill" id="cook-progress-fill" style="width:{100/total}%"></div>
  </div>
  <!-- Steps -->
  <div id="cook-steps" aria-live="polite">
    {for each direction, render a .cook-step div with:}
    <div class="cook-step" data-step="{n}">
      {if matched ingredients exist for this step:}
      <div class="cook-ingredients">
        {for each group with matches:}
        <div class="cook-ingredient-group">
          <div class="cook-ingredient-heading">{groupName}</div>
          <ul class="cook-ingredient-list">
            {for each matched ingredient:}
            <li>{fullIngredientString}</li>
          </ul>
        </div>
      </div>
      {end if}
      <div class="cook-step-text">{step text}</div>
    </div>
  </div>
  <!-- Navigation -->
  <div class="cook-nav" id="cook-nav">
    <button type="button" id="cook-prev" class="cook-btn">{n===0 ? hidden : "Previous"}</button>
    <button type="button" id="cook-next" class="cook-btn">{n===total-1 ? "Finish Cooking" : "Next"}</button>
  </div>
  <script src="/cook.js" defer></script>
</body>
</html>
```

Key implementation details:
- **All steps rendered in HTML** (no-JS fallback per D-04 — without JS, all steps are visible)
- Each step div has `class="cook-step"` and `data-step="{1-indexed step number}"`
- Ingredient panel: class `cook-ingredients` with `cook-ingredient-group`, `cook-ingredient-heading`, `cook-ingredient-list` inside. Only rendered if `matchIngredientsToStep()` returns non-empty array for that step
- Step text: class `cook-step-text`, content is the escaped step string
- Navigation buttons: `id="cook-prev"` and `id="cook-next"` with `class="cook-btn"`
- Exit button: `<a>` linking to `/recipes/{slug}`, has `aria-label="Exit cooking mode"`
- Step counter: `id="cook-step-counter"`, text "Step 1 of {total}"
- Progress bar fill: `id="cook-progress-fill"`, initial width based on step 1
- Progress bar: `role="progressbar"` with `aria-valuenow="1"`, `aria-valuemin="1"`, `aria-valuemax="{total}"`, `aria-label="Cooking progress"`
- `aria-live="polite"` on the `#cook-steps` container
- All user-facing recipe text escaped with `escapeHtml()`
- Body uses `class="cook-mode"` for CSS variable scoping
- `<script src="/cook.js" defer></script>` — the JS file doesn't exist yet (Plan 02 creates it), but the tag is present. Without the file, the page degrades to no-JS fallback.
- Use inline styles on body for `background:var(--cook-bg);color:var(--cook-text)` as fallback until CSS loads, plus Tailwind classes

**5. `recipeCook(request: Request): Response` export** — the route handler:
- Extract slug from URL: `url.pathname.split('/')` → get second-to-last segment (the part before `/cook`)
- Convert slug to filename: `getRecipeFilename(slug)`
- Try `loadRecipe(filename)` — on success, return `renderCookingMode(recipe, slug)`
- On error (recipe not found), return 404 Response with recipe-not-found HTML (same pattern as show.tsx)
