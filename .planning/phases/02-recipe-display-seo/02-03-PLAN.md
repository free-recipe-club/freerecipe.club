  <action>
**Add `@media print` block to the end of `app/styles/input.css`** (after the existing `@theme` block):

```css
@media print {
  /* Hide non-content elements */
  nav { display: none; }
  .recipe-image { display: none; }
  .recipe-background { display: none; }
  input[type="checkbox"] { display: none; }

  /* Reset colors for printing */
  body {
    background: white !important;
    color: black !important;
  }

  /* Flatten links — show URL in parentheses */
  a {
    color: black !important;
    text-decoration: none !important;
  }
  a[href]::after {
    content: " (" attr(href) ")";
    font-size: 0.8em;
  }

  /* Remove brand-cream-muted backgrounds in print */
  .bg-brand-cream-muted {
    background: transparent !important;
  }
}
```

**Per D-10:** Print includes title, ingredients, steps, flavor text, and attribution. Excludes navigation, image, background story, and checkboxes.

**Note on `.recipe-background`:** Per D-10, "No image and no background story in print." The background section uses class `.recipe-background` in the show controller. Flavor text is inside the same section — but D-10 says flavor IS included in print. This means the show controller should separate flavor and background into distinct elements:
- If the show controller from Plan 01 wraps both flavor AND background in `.recipe-background`, the print rule will hide BOTH. 
- The plan 01 action already renders flavor in a `<p>` before background in a `<p>`, both inside the `.recipe-background` section.
- To match D-10 exactly (flavor included, background excluded), the HTML structure should have flavor OUTSIDE the `.recipe-background` wrapper, or use a separate `.recipe-background-text` class only on the background paragraph.

**Resolution:** Add a `print:hidden` class specifically to the background `<p>` element rather than hiding the entire section. Update the print CSS to NOT hide `.recipe-background` as a whole. Instead:
```css
@media print {
  nav { display: none; }
  .recipe-image { display: none; }
  .recipe-background-text { display: none; }
  input[type="checkbox"] { display: none; }
  /* ... rest of print rules */
}
```

**IMPORTANT:** This requires coordinating with Plan 01's HTML. If Plan 01 already executed, the executor should verify the class structure in `show.tsx` and adjust either the CSS selector or add a `recipe-background-text` class to only the background paragraph (not flavor). The key is: flavor prints, background story does not.

**Responsive verification:** The HTML from Plans 01/02 already uses Tailwind responsive classes (text-lg, max-w-2xl, px-4, py-4, space-y-3). Verify that at 320px viewport:
- No horizontal scroll
- Body text is 18px (text-lg)
- Tap targets are 44px+ (py-4 on list items, label wrapping on checkboxes)
- Content fills available width with 16px padding

No additional responsive CSS is needed — the mobile-first Tailwind utilities handle it. This task is primarily about the print stylesheet.
